### Payload + Neon: status and plan

**The backend is decided: Payload + Neon, built the same way as the Giada project** (see [decisions](07-decisions.md)). Details of what exists are in [10-payload-cms.md](10-payload-cms.md). Steps, in order:

1. **Route groups. DONE.** Pages live in `src/app/(frontend)/` (own root layout: Header, Footer, fonts, `globals.css`). Payload is in `src/app/(payload)/` (admin at `/admin`, API at `/api/*`, GraphQL). `favicon.ico` stays at the true `app/` root (so would `robots.ts` and `sitemap.ts`). Each group has its own root layout because Payload's admin needs its own `<html>`/`<body>`.
2. **Config. DONE.** `src/payload.config.ts` (Postgres adapter, Lexical editor, `sharp`, S3 storage plugin that stays off until credentials exist), `withPayload()` in `next.config.ts`, the `@payload-config` alias, `payload-types.ts` and the admin import map generated by `npm run generate:types` / `generate:importmap`, and the `payload`, `generate:types`, `generate:importmap` scripts. `.env.example` added.
3. **Neon. DONE 2026-10-24** (details and proof in [10-payload-cms.md](10-payload-cms.md#neon-set-up-and-verified-2026-10-24)). Project "Learning Paths School" in AWS US East 1, Postgres plus a private object-storage bucket `lps-media`, declared in `neon.ts` (applied with `neon deploy`). `neon init` linked the folder (`.neon`, gitignored) and `neon deploy` / `neon checkout` write `DATABASE_URL`, `DATABASE_URL_UNPOOLED`, `NEON_BRANCH` and the S3 credentials into `.env.local` (gitignored); `PAYLOAD_SECRET` is added by hand. **Still open: the production branch has no tables** (production never creates them; migrations are needed before `/admin` works there).
4. **Collections and globals. DONE for the home page (2026-10-28, local).** `Users`, `Media` and the `home` Global (Content and SEO tabs, drafts, Live Preview); the SEO plugin; see [26-cms-home-plan.md](26-cms-home-plan.md). Other pages: later.
5. **Data layer. DONE for the home page (2026-10-28, local).** `lib/api/home.ts` (Local API in `unstable_cache`, tag `home`, never throws, falls back to `src/data`), `lib/api/home-map.ts` (pure mapper), `HomePageClient.tsx` for Live Preview, `afterChange` hooks and `/api/revalidate` bust the tag.
6. **Webpack or Turbopack. RESOLVED: Turbopack works.** Giada uses Webpack, but Payload 3.91 builds and runs on this project's Turbopack setup (checked with a production build and the real admin in Chrome). No switch needed.

**Cache Components is off.** `cacheComponents` and `partialPrefetching` (the project generator's defaults) were removed from `next.config.ts`. With them on, every `/admin` request logged `Next.js encountered the unstable value new Date() while prerendering` from Payload's `authenticate`. With them off the log is clean and nothing else changed (`/` is still prerendered static). `unstable_cache` and tags, the pattern from Giada, work without it.

Lessons from Giada to carry over (full detail in Giada's `ARCHITECTURE.md`, read-only reference):
- Local dev and the deployed site share **one** Neon database unless a separate branch is used, and the Postgres adapter auto-pushes schema changes in dev. Use a separate Neon branch for local work, and plan real migrations before launch.
- A Global's fields are shown on every edit of that Global. Do not put one-off fields on a Collection for a single document. Give the special page its own Global.
- Importing `getPayload`/`@payload-config` into a Client Component breaks the build. Keep mappers in a separate, Payload-free module.
- Keep `access` rules explicit (editors cannot create users or promote themselves).

- All `payload` and `@payloadcms/*` packages are pinned to the **same exact version** (3.91.0, no `^`). Payload requires them to match. Upgrade them together: `npm install --save-exact payload@X @payloadcms/next@X @payloadcms/db-postgres@X @payloadcms/richtext-lexical@X @payloadcms/storage-s3@X @payloadcms/live-preview-react@X`.
- `@payloadcms/next` supports Next `>=16.3.3 <17`. This project is on 16.4.2, so it is compatible. Re-check when upgrading Next.
- `graphql` (a Payload peer dependency) was installed automatically.
- The Giada project (reference only) uses the same package set.

## Important: this Next.js version has breaking changes

Before writing framework code, read the matching guide in `node_modules/next/dist/docs/`. See `AGENTS.md`.

`next.config.ts` currently:

- Wraps the config in `withPayload()` (from `@payloadcms/next/withPayload`).
- Has a Turbopack rule routing `*.css` through `@tailwindcss/turbopack`. This differs from the `@tailwindcss/postcss` setup in the Next.js docs. It came from the project generator and works, so leave it unless it breaks.
- Does **not** enable `cacheComponents` / `partialPrefetching` (removed, see above).

## Folder structure (current)

Basic skeleton modelled on the Torque Pharma and Giada projects, which share the same layout. Empty folders hold a `.gitkeep` until they get real files. The structure is expected to evolve.

```
lps/
├── src/
│   ├── app/                  # App Router. Two route groups, each with its own root layout:
│   │   ├── (frontend)/       #   the public site: layout.tsx, page.tsx, globals.css
│   │   ├── (payload)/        #   Payload admin (/admin) and API (/api/*), mostly generated
│   │   ├── global-not-found.tsx  # the branded 404 for every unmatched URL (experimental.globalNotFound)
│   │   ├── robots.ts, sitemap.ts  # robots.txt and sitemap.xml
│   │   └── favicon.ico       #   must stay at the app root
│   ├── collections/          # Payload collections: Users.ts, Media.ts
│   ├── payload.config.ts     # Payload config (@payload-config alias)
│   ├── payload-types.ts      # GENERATED by `npm run generate:types`, do not edit
│   ├── components/
│   │   ├── layouts/          # Site-wide shell: Container, Section, Header, Footer, SmoothScroll (Lenis, mounted once in the (frontend) layout), HorizontalScene (pinned scene that pans sideways across panels; panels animate on its scroll timeline via `useSceneTimeline`; row layout at every width unless reduced motion; a last panel taller than the screen is scrolled down through)
│   │   ├── sections/         # Page-specific composed sections
│   │   │   ├── home/         #   one folder per page (add as pages are built)
│   │   │   └── shared/       #   sections reused across pages (CtaSection, MarqueeSection so far)
│   │   ├── blocks/           # BlockRenderer: turns a page's list of blocks (data/home-page.ts) into its sections
│   │   └── ui/               # Small reusable primitives (Badge, ButtonLink, SectionTitle, Accent, BodyText, Photo, TabBar; cards, accordion... to come)
│   ├── data/                 # Static config and copy (footer.ts, header.ts so far); site info, nav items to come
│   ├── fonts/                # Local font files + next/font config
│   ├── lib/
│   │   ├── site.ts           # SITE_URL (NEXT_PUBLIC_SITE_URL), name, description for metadata, robots, sitemap
│   │   ├── useIdleReady.ts   # true once the page has loaded and the browser is idle (or, on phones, once the section is near the viewport): holds back below-the-fold images
│   │   ├── motion.ts         # media queries (MOTION_OK, PHONE, DESKTOP...) and prefersReducedMotion()
│   │   ├── useScrollReveal.ts, useParallax.ts, useViewportVideo.ts  # shared animation behaviour of the sections
│   │   ├── gsap.ts           # registerGsap(): registers ScrollTrigger once
│   │   ├── scroll.ts         # setLenis / scrollToY (programmatic scroll through Lenis)
│   │   ├── actions/          # Server Actions ("use server")
│   │   └── api/              # Data layer: one module per page/resource
│   ├── styles/               # Tailwind @theme tokens (colors, typography)
│   └── types/                # Shared TypeScript types (home/ has one file per section; page.ts: the page-block types)
├── public/                   # Static assets (images/footer/ social icons, images/header/ logo and menu icons)
├── scripts/                  # Image tools: optimize-image.mjs, check-images.mjs (npm run images:optimize | images:check), svgo config, README
├── .prettierrc.json          # Prettier (npm run format | format:check), .prettierignore lists what is not formatted
├── tests/                    # Browser checks: serve-prod.mjs, qa.mjs, interactions.mjs, snapshot.mjs (npm run qa:serve | qa | qa:interact | qa:snapshot), see docs/24-qa-suite.md
├── vitest.config.ts          # Unit tests (npm test): src/**/*.test.ts(x), next to the code they test
├── .github/workflows/ci.yml  # CI: lint, types, unit tests, build, browser checks on every push and pull request
├── .githooks/pre-commit      # lint + types + unit tests before every commit (switched on by npm install)
├── docs/                     # Project documentation (this folder)
├── AGENTS.md                 # Next.js guidance for coding agents (auto-managed by `next dev`)
├── CLAUDE.md                 # Project rules for Claude Code
└── next.config.ts
```

The `@/*` import alias maps to `src/*` (see `tsconfig.json`).

### Content in `data/` + types in `types/`

Copy and links for a component live in `src/data/<name>.ts`, typed by `src/types/<name>.ts`, and the component only renders them. The footer is the first example (`data/footer.ts`, `types/footer.ts`). This keeps text edits out of the markup and makes a later move to a CMS or API a change in one place.

### Tailwind gotchas found so far

- `leading-normal` is `line-height: 1.5`, not CSS `normal`. Use `leading-[normal]` for the font's natural line height.
- An arbitrary `min-[Npx]:` variant does **not** reliably override an `xl:` utility on the same property (it sorts earlier in the CSS). Use `xl:max-[Mpx]:` for the lower range instead of overriding.
- After adding a new CSS file, an incremental build may ignore it. Delete `.next` and rebuild.

### Component folder convention (from Torque/Giada)

```
components/ui/ComponentName/
├── ComponentName.tsx
├── ComponentName.types.ts    # only if the component takes props
└── index.ts                  # export { default } from "./ComponentName";
```

Sections follow the same convention and are named `*Section` (e.g. `HomeHeroSection`).

## Conventions

- TypeScript everywhere.
- Path alias `@/*` maps to `src/*`.
- Layout: build page sections with `<Section>` (main 1520px container + the 200px section spacing, both shared and driven by `CONTAINER_WIDTH` and `--spacing-section`). Do not hard-code container widths or section padding in a section. See [05-design-system.md](05-design-system.md#spacing-and-layout).
- Images: compress before adding, **and check the quality** (measure PSNR, aim for about 45 dB or more; AVIF quality 90 to 92 is a good default for photos, WebP needs 95 or higher to match). `next/image` re-encodes at quality 75 by default (Next 16 only allows qualities listed in `images.qualities`), so for already-compressed hero photos use `unoptimized`, or allow a higher quality in `next.config.ts`. See [11-home-hero.md](11-home-hero.md#images).
- Server Components by default. Add `"use client"` only where interactivity or animation needs it.
- Fonts: local files in `src/fonts/` loaded with `next/font/local` (`src/fonts/index.ts`). Lexend Deca = headings, Plus Jakarta Sans = body. Use the semantic Tailwind classes `font-heading` / `font-body`, never the family names. See [design system](05-design-system.md#typography).
