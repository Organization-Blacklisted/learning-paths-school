# Payload CMS

Payload 3.91.0 runs **inside this Next.js app** (no separate server), backed by Postgres (Neon, not created yet). Built the same way as the Giada project. Setup status and the build plan are in [02-architecture.md](02-architecture.md#payload--neon-status-and-plan).

## What exists

| Piece | File | Notes |
| --- | --- | --- |
| Config | `src/payload.config.ts` | Postgres adapter, Lexical editor, `sharp`, S3 storage plugin, admin title suffix " - Learning Paths School" |
| Users collection | `src/collections/Users.ts` | Email + password auth, `role` field (admin / editor), access rules, first-user rule |
| Media collection | `src/collections/Media.ts` | Uploads with required `alt`, 400x400 admin thumbnail, public read |
| Admin | `src/app/(payload)/admin/...` | `/admin`, generated by Payload. `importMap.js` is generated. |
| API | `src/app/(payload)/api/...` | REST `/api/*`, GraphQL `/api/graphql`, playground `/api/graphql-playground` |
| Types | `src/payload-types.ts` | Generated. Do not edit. |
| Env template | `.env.example` | Names only. Real values go in `.env` (gitignored). |

There are **no globals and no page collections yet**. They are added as pages are designed.

## Scripts

| Command | Purpose |
| --- | --- |
| `npm run generate:types` | Regenerates `src/payload-types.ts`. Run after changing any collection or global. |
| `npm run generate:importmap` | Regenerates `src/app/(payload)/admin/importMap.js`. Run after adding admin components, rich-text features or plugins that add admin components (including **enabling the S3 plugin**). |
| `npm run payload` | Payload CLI (`payload run <script>`, migrations, ...). |

Both generate commands only read the config. They do not connect to a database.

## Access rules (Users)

- **admin:** full access.
- **editor:** can edit site content. Cannot create or delete users, cannot read other users, cannot change their own role. The `role` field has its own field-level lock, because otherwise "an editor may update their own record" would let them promote themselves.
- **The very first account is always an admin**, whatever the Role dropdown says (a `beforeChange` hook). Without it the first account would get the default `editor` role and nobody could manage users (Giada hit this). The form still shows "Editor" selected, and the field description says so.
- Anonymous users cannot list users (403). Media is publicly readable.

## Environment

See `.env.example`. Nothing is required to build the site, but the admin and API need a database.

| Variable | Used for |
| --- | --- |
| `PAYLOAD_SECRET` | Signs admin sessions. Required at runtime. Generate a random 64-character hex string. |
| `DATABASE_URL` | Postgres connection string (Neon pooled URL). |
| `DATABASE_URL_UNPOOLED` | Direct (unpooled) Neon URL, for migrations and tooling. Not read by the app yet. |
| `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_ENDPOINT_URL_S3`, `AWS_REGION` | Neon Object Storage. When `AWS_ENDPOINT_URL_S3` and `AWS_ACCESS_KEY_ID` are empty the storage plugin is **off** and uploads go to the local, gitignored `/media` folder. |
| `REVALIDATE_SECRET` | Future `POST /api/revalidate` cache busting. Not used yet. |

Until `DATABASE_URL` points at a real database, `/admin` and `/api/*` return errors. The public pages do not need it yet.

## How it was verified (2026-10-19)

No Neon project exists, so everything was tested against a **throwaway real Postgres** (embedded, in a temp folder outside the project, deleted afterwards). Nothing touched a real database.

- Lint and typecheck pass. Production build passes: `/` is still static; `/admin`, `/api/*` are dynamic.
- Access rules, via Payload's own API (6 of 6): the first user becomes an admin even when editor is submitted; the second user defaults to editor; an editor cannot create users; an editor cannot promote themselves; an editor sees only their own record; an admin sees all.
- In Chrome against the production build (14 of 14): the public home page still renders with header, footer and fonts; `/admin` redirects to "create first user" when there are no users; the tab title is "Create first user - Learning Paths School"; creating the first user through the real form lands on the dashboard; `/api/users/me` reports that user as `admin`; the Users, Media and Account screens render; anonymous `GET /api/users` is 403; anonymous `GET /api/media` is 200; GraphQL answers; an unknown URL returns HTTP 404; no console errors; no server errors in the log.

**Not verified:** anything against Neon, and file uploads (the local `/media` path and the S3 path were not exercised). The Live Preview and drafts features are not set up yet.

## Known limitations and gotchas

- **Unknown URLs: solved on 2026-10-21.** With two root layouts Next has no single layout to wrap unmatched URLs in, so they showed a plain 404 without header and footer. `src/app/global-not-found.tsx` (experimental, enabled in `next.config.ts`) now renders a branded 404 with its own `<html>`, fonts, header and footer (HTTP 404, `noindex`). The copy is mine; the real design is still to come. A `not-found.tsx` inside `(frontend)` would cover `notFound()` calls from pages, not unmatched URLs.
- **Without a database, `/admin` and `/api/*` answer 500 in production** (they cannot connect); the static public pages are unaffected. See [16-production-readiness.md](16-production-readiness.md).
- **Cache Components is off** (see [architecture](02-architecture.md#payload--neon-status-and-plan)).
- **Dev auto-creates tables, production does not.** Payload's Postgres adapter pushes schema changes automatically only when `NODE_ENV` is not `production`. So running `npm run dev` against a shared database changes that database immediately, and there are **no migration files**. Use a separate Neon branch for local work, and create real migrations before launch.
- **Do not run a second `next dev` in this folder.** Next.js allows one dev server per project. If one is already running, another start fails with "Another next dev server is already running".
- **Do not delete `.next` while a dev server is running.** Builds can run alongside dev (dev uses `.next/dev`), but wiping `.next` removes the dev server's cache.
- **Changing a collection** needs `npm run generate:types`. **Adding an admin component, rich-text feature or enabling the S3 plugin** needs `npm run generate:importmap`.
- The admin has Payload's default look. Giada also customises the admin logo, theme and thumbnails; not done here.
- `/api/graphql-playground` is the generated default. Consider removing the GraphQL routes if GraphQL is not going to be used.
